# specialists/

Seven small **trained** models, one per runtime security agent (Scout, Probe, Trace, Diagnose,
Patch, Fortify, Verify). They are machine-learning components with their own datasets, training
runs, versioned checkpoints and held-out evaluations, not prompts. Claude still does the
open-ended reasoning; each specialist runs first and its ranked output goes into that agent's
Claude prompt as advisory, provenance-labelled data:

```
code intelligence → specialist model → Claude (when needed) → authorized tools → executed evidence
```

## What is real, and what is not (read first)

- **Real:** every model below was trained here (NumPy, CPU, seconds per model). Its weights, dataset
  hash, configuration and held-out scores are in `specialists/checkpoints/<agent>/manifest.json`.
  The orchestrator loads them (SHA-256 verified) and calls them in every assessment; each call is an
  audited `specialist.inference` event in the assessment's hash-chained audit log.
- **Synthetic training data.** The code corpus is generated (`data/corpus.py`: 12 CWE classes ×
  4 code-shape families × FastAPI/Flask/Express, vulnerable / minimal fix / incomplete fix). Trace and
  Fortify use the pinned public MITRE catalogs (CAPEC, CWE, ATT&CK, D3FEND) in `standards/`. No
  customer repository, private code or third-party code is used. Scores on synthetic data say how
  well a model generalises to an unseen *code shape*, not how it does on arbitrary real codebases.
- **Only models that beat their baseline with statistical support are used.** A model is
  *promoted* only when the paired-bootstrap 95% interval of its gain over the strongest
  deterministic baseline excludes zero on held-out data. An unpromoted model's checkpoint still
  ships, but the agent receives that **baseline's** answer (labelled `source: baseline:<name>`).
- **Live comparison started, not conclusive:** one valid live assessment per configuration
  (Claude-only, hybrid). Both found and fixed both planted defects. One run each cannot show an
  improvement or a regression; see [Live comparison](#live-comparison-claude-only-vs-hybrid).
  Nothing here claims the models outperform Claude.

Leave-one-family-out cross-validation (each of the four families per class is the unseen test
set once), mean primary metric: Scout 0.350 vs regexes 0.098; Diagnose 0.475 vs lookup 0.574;
Patch 0.751 vs lookup 0.750; Verify 0.976 vs heuristics 0.857.

Scout as a detector on the test split (any CWE = flagged): precision 0.76, recall 0.49,
false-positive rate 0.31, false-negative rate 0.51. The platform's regex patterns: precision 0.75,
recall 0.08, FPR 0.06, FNR 0.92. The model finds about six times more of the vulnerable spans at
the cost of more false positives; that trade is why it only *ranks* spans and never drops or raises
a hypothesis on its own.

**Out-of-distribution check** on the authorized planted-defect target `examples/payments-lite`
(never trained on; `python -m specialists.fixture_eval`, `results/fixture_payments_lite.json`):
Scout ranks the planted IDOR (`GET /payments/{payment_id}`) 2nd of 8 handlers and the refund-bound
defect 5th of 8; its top pick, `GET /health`, is a false positive. The regex patterns flag neither.
Probe's top strategy maps to the labelled check category for both. Verify's training data was
corrected after its first version rated this target's (good) patch as "test_weakened": correct
patches that *add* a regression test were missing from the corpus. That fix was informed by this
target, so the target is no longer an independent test for Verify.

Cost and latency: inference is pure Python in the worker (no NumPy/torch at runtime), 0.07–1.7 ms
per call, no tokens, no external calls. Checkpoints total about 21 MB.

## The seven models

| Agent | Architecture | Inputs (hashed features) | Labels | Dataset (train / val / test) | Split |
|---|---|---|---|---|---|
| Scout | MLP 16384→96→13, ReLU, softmax | `code` | 12 CWEs + safe | 3240 / 648 / 1296 | by code family |
| Probe | MLP 8192→48→12 | `hypothesis`, `cwe` (25% wrong, 15% missing) | 12 WSTG tests | 960 / 480 / 480 | by phrasing family |
| Trace | linear 4096→10, sigmoid | `name` (CWE name) | ATT&CK tactics | 91 / 17 / 21 | by CWE |
| Diagnose | MLP 16384→64→6 | `code`, `cwe`, `evidence` | `CauseClass` | 1080 / 216 / 432 | by code family |
| Patch | MLP 16384→64→N | `code`, `cwe` | remediation strategies | 1080 / 216 / 432 | by code family |
| Fortify | linear 4096→N, sigmoid | `name`, `tactics` | D3FEND techniques (≥15 uses) | 220 / 24 / 32 | by ATT&CK parent technique |
| Verify | MLP 16384→64→4 | `diff`, `tests` | adequate / incomplete_fix / test_weakened / no_security_change | 4320 / 864 / 1728 | by code family |

Features: word unigrams/bigrams and character trigrams, crc32 signed hashing, log counts,
L2-normalised **per field** (so a one-token CWE weighs as much as a long code span). Training:
mini-batch Adam, L2 weight decay, dropout on the hidden layer, early stopping on validation loss,
fixed seeds. The pure-Python inference path is checked against NumPy on every test row
(`numpy_parity_argmax: 1.0`).

## How the agents use them (and what they cannot do)

`security_agents/specialist_bridge.py` and `workflow/orchestrator.py`:

| Agent | When | Effect |
|---|---|---|
| Scout | before its Claude step: scores every entry-point handler span | ranking block in the prompt; afterwards re-ranks hypotheses (35% weight). Cannot add or drop one; citations are still validated |
| Probe | per hypothesis | ranked WSTG strategies in the prompt. The executed check template decides the outcome |
| Trace | per confirmed finding | tactics in the prompt. Severity stays the deterministic CVSS computation |
| Diagnose / Patch | per finding | likely root cause / remediation strategy in the prompt |
| Fortify | per hardened finding | D3FEND candidates for the finding's mapped ATT&CK technique; mappings stay `proposed` |
| Verify | after the executed checks | if it rates the evidence other than adequate on an accepted patch, a note asks for human review. **The verdict is never changed**: `compute_verdict()` decides from executed records |

Tests that pin this down (`security-agents/tests/test_specialist_integration.py`): all seven
agents produce audited inferences with model ids and the advice reaches the prompt; disabled or
corrupt checkpoints fall back and the assessment completes unchanged; a hostile model that calls
every patch adequate cannot get an ineffective patch accepted; one that calls a good patch
incomplete only adds a note. `SPECIALISTS_DISABLED=1` turns them off.

## Commands

```bash
uv sync --all-packages && uv pip install numpy        # numpy is for training only
uv run python -m specialists.train                    # build datasets, train, evaluate, write checkpoints + results
uv run python -m specialists.train scout verify       # a subset
uv run python -m specialists.fixture_eval             # out-of-distribution check on payments-lite
uv run pytest -q specialists/tests                    # checkpoints, hashes, fallback, split hygiene, results match
```

Re-running training is deterministic (seeded); the dataset SHA-256 in each manifest must match
`digest(BUILDERS[agent]())`, which a test asserts.

## Live comparison: Claude-only vs hybrid

`python -m specialists.live_comparison` runs the full seven-agent assessment on
`examples/payments-lite` (authorized, owned fixture) in each configuration, interleaved, and scores
each run against `labels.yaml` `planted_findings` / `negatives` (the answer key — agents never see
it). Agents do receive behavioral expectations from the same file's `expectations:` section (routes
and invariants also stated in the target README); discovery is therefore with intended-behavior
context, not a fully blind hunt. Results go in
[`results/live_comparison.json`](results/live_comparison.json) (every run, the summary, excluded runs).
`--resume` refuses if mode or settings differ from the file on disk.

- `claude_only`: `Orchestrator(specialists=Specialists(enabled=False))`
- `hybrid`: the deployed specialists (Scout, Probe, Verify models; baselines for the other four)
- `specialists_only`: the specialists' advice for the planted spans, without Claude

Settings: `claude-opus-5-5` for all roles, `--max-hypotheses 3 --validate 2`, $4 cap per run.

**Status: one usable run per configuration, so there is no comparison yet.** Six runs were
started ($7.04 in total). After three of them the provider returned `LLM_UNAVAILABLE` on every
call: one Claude-only run failed in Patch after spending $1.79, and three runs failed at Scout's
first turn ($0). Those four are excluded and listed in `excluded_runs`. The provider failures are
an outage or credit problem, not agent behaviour; `provider_failure()` keeps model refusals in
the results.

| Per assessment (n = 1 each) | Claude-only | Hybrid |
|---|---|---|
| IDOR `GET /payments/{id}`: hypothesised / validated / correct diagnosis / fixed, Verify accepted / hardened | yes / yes / yes / yes / yes | yes / yes / yes / yes / yes |
| Refund bound `POST /refunds`: same stages | yes / yes / yes / yes / yes | yes / yes / yes / yes / yes |
| Rank of IDOR / refund hypothesis after Scout | 1 / 2 | 1 / 2 |
| CWE reported for the refund defect (label: CWE-840) | CWE-841 | CWE-1284 |
| Confirmed false positives; hypotheses on the three lookalike routes | 0; 0 | 0; 0 |
| Tokens | 495,385 | 499,896 |
| USD | $2.65 | $2.59 |
| Wall clock | 441 s | 406 s |

Per agent, USD (Claude-only → hybrid): Scout 0.19 → 0.21, Probe 0.16 → 0.17, Trace 0.40 → 0.45,
Diagnose 0.37 → 0.37, Patch 0.74 → 0.62, Verify 0.17 → 0.14, Fortify 0.61 → 0.63. All 14 agent
runs succeeded. In the hybrid run the Scout specialist did not change the hypothesis order. The
Verify specialist rated one of the two accepted patches `test_weakened` (0.61) and added a
human-review note. The verdict stayed accepted, as designed. Whether that note is right or a false
alarm was not checked by hand.

What these numbers can and cannot say:

- Both configurations solved the whole task once. The fixture has two planted defects, so the
  task has no headroom: Claude alone already gets both. On this target a hybrid gain could only
  show up as cost or latency, and with n = 1 a 2% USD or 8% latency difference is within ordinary
  run-to-run variation. **No improvement is shown.**
- A Wilson 95% interval on 1/1 is [0.21, 1.0]. Telling the configurations apart needs many more
  runs and a target where Claude-only misses things.
- The excluded Claude-only run fixed the IDOR (Verify accepted) and validated the refund defect,
  then Patch hit the provider failure. It is not counted.

Specialists only (no Claude, deterministic): Scout ranks the IDOR handler 3rd and the refund
handler 4th of 8 (top pick `GET /health`, a false positive). The CWE it gives each is in the
right family. Probe's top strategy maps to the labelled check category for the IDOR but not for
the refund bound (`WSTG-INPV-12`). The Diagnose baseline gives `missing_check` for both, which is
right for the IDOR and wrong for the refund bound (`wrong_check`). Validation, patching and
verification need executed checks, so this configuration cannot do them. Trace and Fortify have
no answer key in `labels.yaml`.

To finish (costs money; needs a working key):

```bash
RUN_LIVE_LLM_EVAL=1 LIVE_SEVEN_MAX_USD=4 uv run python -m specialists.live_comparison \
    --mode live --i-have-authorization --reps 5 --total-max-usd 30 --resume
```

`--resume` keeps the runs already recorded. A free replay check of the harness (scripted, not evidence):
`uv run python -m specialists.live_comparison --mode replay --reps 1 --out /tmp/replay.json`.

## Data and privacy

- **Training data:** only the generator in `data/corpus.py` and the pinned MITRE catalogs (licences in
  `standards/standards/data/LICENSE-*`). The training code reads nothing else; there is no path
  from customer repositories, snapshots or findings into training.
- **At inference:** models run inside the worker process; the code spans they score never leave it.
  Claude still receives the code spans the agents read (as before this change) through the
  existing LLM gateway, redactor and budgets.
- Persistent memory (findings history, snapshots, expectations) is unchanged and is not training.
