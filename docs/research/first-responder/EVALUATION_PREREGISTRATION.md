# Future preregistration — DRAFT, BLOCKED, NOT AUTHORIZATION TO EXECUTE

This phase performs no formal data collection, scenario rollout, training or policy
comparison. This document is a future protocol design, not a completed numerical
preregistration. Every unresolved value below must be approved and committed before
any collection; no threshold can be chosen from comparative outcomes.

## Next proposed experiment

An owned isolated instrumentation and agent-effect feasibility comparison: freeze
Grok's actual deterministic first responder as primary reference and compare a
budget-aware deterministic heuristic using the same permitted read-only capabilities.
First establish whether agent results change later actionable decisions and whether
cost, latency and independent outcome labels are reliable. No learned policy in this
initial experiment. Existing frozen v6 is not comparable because its observation,
action, reward and safety semantics differ. No implementation of this experiment is
included here.

Proposed scenario families: known vulnerable endpoint symptoms; repeated auth failures;
unexpected access patterns; resource pressure; recurrence of verified vulnerability;
conflicting evidence; benign lookalikes; concurrent low-priority incidents. Only owned,
authorized isolated applications. These are taxonomy labels, not authored/consumed
holdout cases. Independent evaluators must author and seal future evaluation instances.
Historical exposed scenarios/holdouts cannot become independent new evaluation data.

## Freeze before execution

Pin environment/app/commit/deployment, telemetry replay or owned execution mode,
provider/model/prompt/toolchain versions, capability/input DAG, decision schema,
mask/expiry semantics, policy/config versions and baseline implementations. Register
same observations, scopes, tool/model access, budget and latency accounting for every
policy. Do not handicap Grok by withholding existing valid workflow context. If an
agent service is stochastic, distinguish replay comparability from live call effects;
freeze seeded artifact schedules where justified and disclose approximation limits.

Specify train/validation/evaluation partitioning by incident/application/version and
attack family as appropriate to prevent related-code or repeated-window leakage.
No training split is used in the proposed non-learning feasibility step. Never split
windows of one incident across partitions. Seal independent evaluation instances and
labels; no tuning from them. A later learning experiment requires separate authorization
and a frozen training dataset, environment fidelity assessment and policy candidates.

Primary endpoint selection, actionable-escalation rubric, required correctness level,
horizon and censoring are **UNAPPROVED/TBD**. Candidate paired endpoints: time to
independently actionable escalation and correct-escalation rate. Secondary metrics:
detection-to-investigation delay, adjudicated evidence value, invocation count/charged
cost, analyst workload, false/missed escalation, resolution quality, decision
reproducibility and recommendation accuracy. Containment impact is unavailable unless
independently measured under separately authorized execution; do not substitute claims.
Report every policy and family, raw failures and eligibility under each constraint.

Sample methodology: independently choose a precision target/minimum meaningful effect
and power/error control before collection; use external variance information or a
separately approved noncomparative instrumentation pilot. Account for incident-level
clustering, stochastic agent/model replicates and multiple endpoints/families. Paired
incident comparisons and incident-cluster confidence intervals are candidates; exact
method, number of incidents/replicates, minimum family coverage and missing-outcome
handling are **UNAPPROVED/TBD**. Decision windows are not independent samples. Report
uncertainty and coverage, not only pooled means. No inherited 600-episode count.

Compute wall time/CPU/RAM/storage, provider USD/tokens, per-role and total tool calls,
turns, per-incident concurrency/latency, analyst workload, intervention durations and
security constraints are **UNAPPROVED/TBD** and require owner approval. Existing role
caps are upper bounds, not authorization to consume them. Register a hard total ledger
and independent stop mechanism. No implicit permission for paid calls in this design.

## Integrity, acceptance and stopping

Execution integrity failures stop the study and preserve all evidence: invalid masks
or actions, foreign scope/context, information leakage, unreconciled charge/accounting,
unsupported clock comparison, unresolved terminal tasks/outcomes, resource exhaustion,
unauthorized execution or missing independent truth. No automatic retries, replacement
seeds, favorable exclusions or selective reruns. Retain partial artifacts and causes.
Ordinary threshold violations are acceptance failures: retain/report all policy/family
outcomes and mark the policy ineligible under that constraint; continue the fixed
comparison only if the future approved protocol permits and integrity remains intact.

Archive source/environment hashes, immutable decisions, receipts, masks, costs,
provenance and sealed-label access audit. Preregister the exact metric scripts and
reproducibility checks. Any protocol amendment must precede affected execution and
be visible. New training, promotion or customer enforcement never follows automatically.

## Gate to a later learning comparison

Compare strong rules/fixed workflow, budget heuristic and justified planning first.
Supervised routing requires reliable expert labels; bandits require meaningful
near-immediate outcomes/coverage; constrained DDQN requires discrete actions, measured
delayed effects, faithful environment and independently enforceable constraints.
Only unresolved sequential residual value plus approved data and explicit owner
permission would justify a separate learning preregistration. This draft grants none.
