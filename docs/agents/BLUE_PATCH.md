# Agent 5 — Patch (Blue team)

Status: **specified**. Contract base: [AGENT_CONTRACT](AGENT_CONTRACT.md).

## Purpose
Produce a minimal candidate diff that implements an approved remediation plan,
with tests, in an isolated worktree.

## Responsibilities
- Create worktree from snapshot SHA; edit only files in `plan.files_expected`
  plus new test files.
- Add or update tests from the plan's test plan (new tests; not edits to tests
  that encode confirmed expectations).
- Run the relevant tests in a `test-runner` sandbox and iterate within budget.
- Emit diff artifact and local test results.
- On retry, use Verify's rejection reasons (not Verify's transcript).

## Not responsible for
Judging whether the patch is correct (Verify), merging, opening PRs, changing
dependencies (flag instead).

## Input — `PatchInput`
`finding_id`, `remediation_plan_id`, `approval_id`, `attempt`, prior
`VerificationResult.reasons` (if retry), context pack (`patch.implement`).

## Output — `PatchOutput` → `PatchCandidate`
`diff_uri`, `diff_sha256`, `files_changed`, `tests_added`, `local_test_run_id`,
`notes`, `deviations_from_plan: [str]` (non-empty → Verify fails diff-scope check
unless deviation is new tests).

## Tools & permissions
`code.read_span`, `code.search`, `graph.*`, `expectations.for_subject`,
`worktree.write_file`, `worktree.diff`, `tests.run`. Sandbox `test-runner`,
network none. Write: worktree only.

## Authorization & controls
- Requires an `approved` remediation `Approval` (orchestrator gate).
- Worktree path is generated by the platform; writes outside it rejected.
- No push, no PR, no access to GitHub tokens.

## Budget
20%; 8 min; ≤ 30 tool calls; max 2 attempts per finding.

## Handoff
→ Verify with PatchCandidate ID only.

## Success criteria / metrics
- Verify acceptance on attempt 1 / attempt 2 / unresolved rates.
- Diff size (lines) vs human reference fix on fixtures.
